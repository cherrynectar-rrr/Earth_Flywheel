30-SECOND EXPLANATION

先别想“AI 很玄学”。把它当成一个会思考的电脑助手。

普通聊天 AI 的核心动作是“你问一句，它答一句”。Horizon 想解决的是另一件事： 一个目标交给它之后，它如何记住进度、使用工具、碰到敏感操作停下来问你，并且以后还能继续。

普通聊天 AI

一次对话，一次回答

  • 主要输出文本
  • 工具权限常常和模型能力混在一起
  • 任务结束后很难稳定继续
  • “会不会做”和“可不可以做”容易混淆

Horizon Agent

有状态、有边界的 Agent Runtime

  • 能记忆、读网页、操作浏览器、维护工作区
  • 敏感动作先经过权限与人工批准
  • 有验证、日志、Git checkpoint 和 Scheduler
  • 模型可以更换，权限与运行时不必推倒重来

Horizon 最重要的一条原则

模型 ≠ 权限 · 工具存在 ≠ 可以调用 · 可以调用 ≠ 可以随意改变现实世界

WHAT IT CAN ACTUALLY DO

不是 Demo 截图：这些能力已经跑通过。

这里写“已经验证过的能力”，不把未来计划冒充成现成功能。

01

记住有用的信息

长期偏好可以保留；临时任务不污染长期记忆；同一事实换个说法重复提交也会被去重。

02

自己读网页

公共网页可以搜索、读取、渲染、截图，同时屏蔽 localhost / 私网目标。

03

登录时把控制权交还给人

遇到账号、Passkey、验证码时，弹出真正的 Chromium 窗口让你处理，完成后继续使用同一会话。

04

受控操作网页

普通点击与非敏感填充可以先生成 action ticket；只有你批准后才会执行，而且 ticket 会过期、只能用一次。

05

安全保存秘密

秘密放在 Windows 用户级加密存储里。模型没有“把密码读出来”的工具。

06

接外部 App，但默认什么都不给

MCP / Connected-App 框架已经存在；GitHub、Notion、Google、Slack 等真实 provider 当前仍为 0 enabled。

07

安全维护 Git 工作

可以做受控的 status / diff / checkpoint；push、force、reset --hard、rebase 等高风险操作不暴露。

08

定时醒来检查任务

Windows 每 15 分钟触发 Scheduler tick；当前生产 recurring jobs = 0，因此不会在后台偷偷干活。

SAFETY BY DESIGN

有些东西不是“还没做”，而是故意不让它自动做。

能力越强，权限边界越重要。Horizon 当前宁可多停一次问人，也不把高风险动作藏在自动化里。

默认拒绝Capability Gateway 默认 DENY，工具存在不代表可调用。
秘密不进模型密码、2FA、token、Passkey 不进入 Memory、日志和普通工具输出。
高风险浏览器动作锁死支付、购买、删除、发布、发消息、转账等不属于 v0.1 自动权限。
真实 App 仍未启用Connected-App framework active ≠ GitHub / Notion / Google 已授权。
真实 Git 仓库仍受保护发现分叉或 dirty worktree 时，不让 Agent 直接提交、merge 或 rebase。
定时器不是后门Scheduler 只能运行固定 check/eval；不能排任意 shell、任意 Agent prompt 或高风险动作。

WHAT MAKES IT DIFFERENT

Horizon 的特色不是“工具数量”，而是工程纪律。

一个 Agent 越能改现实世界，越不能只靠“相信模型会自觉”。

Stable Core, replaceable capabilities

模型、Memory、Router、工具都可以换；Core、Authority 与运行时接口尽量稳定。

Human-owned authority

目标、架构决策、真实账号权限和敏感动作，最终权力属于人，不属于模型。

Evidence before promotion

每个 Phase 都要留下 smoke、eval、release gate 和建设日志，避免“感觉能跑”就晋级。

Graceful degradation

Memory 或某个 capability 出问题，不应该把 Core 一起拖死。

No architecture by accident

实现细节如果开始改变权限或系统边界，就必须提升为架构决策，而不是悄悄发生。

Deliberate incompleteness

0 providers、0 recurring jobs、受保护 Git repo 不是“没做完”，而是安全边界的真实状态。
